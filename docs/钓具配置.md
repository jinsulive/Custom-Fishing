# 钓具配置

- 鱼竿：`core/src/main/resources/contents/rod/default.yml`
- 鱼饵：`core/src/main/resources/contents/bait/default.yml`
- 鱼钩：`core/src/main/resources/contents/hook/default.yml`
- 宝箱 / 袋：`contents/item/treasure_crates.yml`、`contents/item/special_treasures.yml`
- 产出权重：`core/src/main/resources/loot-conditions.yml`

> 术语约定：下文的「+N」指该标签在对应战利品池中的**权重加成**，只对已经在池内配置了该标签的鱼生效。
> 鱼饵与鱼钩必须装在钓竿上才生效。

## 五、几条配置硬约束

1. **权重表只能引用 item / entity / block 三类 ID**。本版本 `ConfigType` 里只有这三类调用 `registerLoot`，hook / bait / rod / util 的注册被注释掉了，写进 `loot-conditions.yml` 必报 `Illegal weight operation: <id>:+N. Id <id> is not valid`。
2. **`to-inventory` 只对 ITEM / ENTITY 型战利品生效**。BLOCK 型在 `CustomFishingHook` 里被硬编码为召唤 FallingBlock，读不到这个字段 —— 这也是四个宝箱从 block 改为 item 的原因。
3. **引用本插件自定义物品必须写 `CustomFishing:<id>`**，provider 名区分大小写；直接写 id 会被当原版 Material 解析。
4. **原版物品在 `give-item` 里写大写 Material 名**（如 `DIAMOND`），解析路径是 `Material.valueOf(...)`。
5. **`block` 型不支持 `price`**（那是 ITEM 型函数）；`chest` 只能用 `directional-4`，`barrel` 可用 `directional-6`。
6. **所有开箱 / 开袋道具末尾必须有 `item-amount: -1`** 自消耗，否则可无限开。
7. **`apple_crate` / `carrot_crate` 只保留定义、不进权重表**：两者仍在 `contents/block/default.yml`（`show-in-fishfinder: false` + `disable-stat: true`，不进图鉴、不计入统计），但 `loot-conditions.yml` 里已删除其权重，因此不会自然钓出，只能用 `/customfishing items give <id>` 直接获取。**不要把它们从该文件删掉、也不要留成纯注释空文件**：`ConfigManager#loadData` 走 `YamlDocument.create`，空文档（root 为 null）会抛 `ConstructorException`，日志刷 `Could not load config file ... Is it a corrupted file?`。
