# 钓鱼大赛

- 配置位置：`core/src/main/resources/contents/competition/default.yml`
- 关联配置：`config.yml` 的 `global-effects`、`other-settings.competition`、`mechanic-requirements`

## 一、两个赛事的基本参数

| 项目 | 周末钓鱼大赛 | 每日钓鱼大赛 |
|---|---|---|
| 配置 ID | `weekend_competition` | `daily_max_size_derby` |
| 胜负条件 | `RANDOM`（每场开赛时随机抽一种） | `RANDOM`（每场开赛时随机抽一种） |
| 开赛日 | 周日（`start-weekday: [7]`） | 周一至周六（`1`~`6`） |
| 开赛时间 | 10:00 | 10:00 |
| 单场时长 | `43200` 秒（12 小时，10:00–22:00） | `43200` 秒（12 小时，10:00–22:00） |
| 开赛人数门槛 | `min-players: 2` | `min-players: 1` |
| 每周场次 | 1 场（周日） | 6 场（周一至周六） |
| 奖励 | 515 憨币+鲸元券 ×1 / 255 憨币+深渊宝藏箱 ×1 / 155 憨币+精制钓具箱 ×1 | 515 憨币+秘法鱼饵袋 ×5 / 255 憨币+秘法鱼饵袋 ×3 / 155 憨币+秘法鱼饵袋 ×2 |
| 参与奖 | 无 | 无 |

- 两个赛事的 `goal` 均为 `RANDOM`：`Competition` 构造期用 `CompetitionGoal.getRandom()` 从
  `CATCH_AMOUNT` / `MAX_SIZE` / `MIN_SIZE` / `TOTAL_SIZE` / `TOTAL_SCORE` 中抽一种（`RANDOM` 本身不再参与抽取），
  抽中的结果写进 `publicContext`，所以开赛播报里的 `{goal}` 显示的就是本场真实目标。
- 每日赛原名「海王巨物赛」，随机目标上线后已改名为「每日钓鱼大赛」。
- 两个赛事的开赛日互补（周日 vs 周一至周六），不会在同一天产生调度冲突。

## 二、时间线

| 时段 | 周一至周六 | 周日 |
|---|---|---|
| 10:00–22:00 | 每日钓鱼大赛（目标随机） | 周末钓鱼大赛（目标随机） |

每天只开一场，比赛中途不重开、不追加场次。

## 三、计分与参赛

- 目标随机后，六种判定都可能出现：
  - `CATCH_AMOUNT`：钓获数量累加，钓到什么不重要；
  - `MAX_SIZE` / `MIN_SIZE`：只记单条最大 / 最小体长，不累加；
  - `TOTAL_SIZE`：所有渔获体长累加；
  - `TOTAL_SCORE`：按战利品分数累加。
- 只有带 `size` 标签的渔获才参与体长类计分；宝箱、鱼钩、杂物这类无体长条目既不计分，也不会让玩家被计为参赛者。
- 参赛为自动加入：比赛期间第一次成功钓获（计入分数的渔获）时加入，并收到 `participate-actions` 提示。
- `participate-requirements`：周末赛配置为 `{}`（无门槛），每日赛未配置该项。
- 人数门槛比较的是**全服在线人数**，不是报名人数。周末赛在 10:00 在线不足 2 人时触发 `skip-actions` 广播「参与人数不足，本场周末钓鱼比赛已取消」，当天不再开赛；每日赛在线 1 人即开赛。
- 管理员查看实时排行榜：`/cfishing competition rank [count]`（权限 `customfishing.command.competition`）。表头输出赛事 ID、获胜条件、剩余时间与参赛人数，随后按名次逐行列出「名次 + 玩家 + 成绩」（前三名配金银铜色，体长类目标成绩带 `cm`）；`count` 默认 10、最大 100。无进行中比赛时提示「当前没有正在进行的比赛」，尚无有效成绩时提示「当前暂无有效成绩」。

## 四、界面展示

| 项目 | 周末赛 | 每日赛 |
|---|---|---|
| BossBar | `enable: false`（已关闭，避免 12 小时赛程长期遮挡视野） | `enable: false`（已关闭） |
| BossBar 行数 | 3 行文案已保留，每 200 tick（10 秒）轮换 | 2 行文案已保留，每 160 tick（8 秒）轮换 |
| 刷新频率 | 20 tick | 20 tick |
| 仅参赛者可见 | 是 | 是 |
| ActionBar | `enable: false`（已写好 3 行文案但未启用） | 未配置 |
| 周期排行广播 | `enable: true`，`interval: 36000`（30 分钟一次） | `enable: true`，`interval: 36000`（30 分钟一次） |
| 全服公告 | 开赛 1 次 + 结算 1 次 | 开赛 1 次 + 结算 1 次 |

倒计时统一使用 `{hour}{minute}{second}`：`{minute}` 在代码里只取「剩余秒数对小时的余数再换算」，单独使用会丢掉小时（12 小时赛在整点会显示成「0 分钟」），因此必须三个连写。

其他占位符：`{rank}`、`{1_player}`、`{1_score}`、`{score_formatted}`、`{goal}`。
由于目标随机，配置文案里的成绩**不再手写单位**（旧版固定写 `cm`，抽到数量/分数目标时会显示成错误单位）；
`/cfishing competition rank` 由 `RankCompetitionCommand` 按目标自动补单位（`max_size`/`min_size`/`total_size` → `cm`）。

## 五、奖励

| 名次 | 周末赛 | 每日赛 |
|---|---|---|
| 第 1 名 | 515 憨币 + 鲸元券 ×1 | 515 憨币 + 秘法鱼饵袋 ×5 |
| 第 2 名 | 255 憨币 + 深渊宝藏箱 ×1 | 255 憨币 + 秘法鱼饵袋 ×3 |
| 第 3 名 | 155 憨币 + 精制钓具箱 ×1 | 155 憨币 + 秘法鱼饵袋 ×2 |
| 第 4 名及以后 | 无 | 无 |

- 货币通过 `money give {player} <数量>` 发放，每档同时发一条对应文案的私聊消息。
- 物品奖励统一走 `give-item` + `to-inventory: true`（直接进背包，背包满时掉落）：
  - `CustomFishing:whale_coupon` 鲸元券 —— 商业街抽奖凭证；
  - `CustomFishing:abyssal_treasure_chest` 深渊宝藏箱 —— 深海专属宝箱（可开出海洋之心、风暴/寒霜钓竿）；
  - `CustomFishing:tackle_crate` 精制钓具箱 —— 通用钓具补给（鱼钩 + 诱饵）；
  - `CustomFishing:mystic_bait_pouch` 秘法鱼饵袋 —— 必得基础诱饵，另有概率出环境特化饵料。
- 两个赛事的 `rewards` 都保留了第 4 个子键 `participation`，动作是 `type: message` + `chance: 0`，永不触发 —— 原因见第七节第 3 条。

## 六、与竞赛相关的外部配置

- `config.yml` 的 `global-effects.effect_1` 是 `conditional` 类型，条件为 `competition.ongoing: true` 且 `id` 包含 `weekend_competition`，效果为 `wait-time-multiplier: 0.85`。该加成作用于所有在线玩家，不只参赛者，覆盖周日 10:00–22:00 整个时段；`id` 列表中不含 `daily_max_size_derby`。
- `config.yml` 的 `other-settings.competition`：`redis-ranking: false`、`server-group: "default"`、`placeholder-limit: 3`（最多支持 `{1_player}`~`{3_player}` 这类占位符）。
- `config.yml` 的 `mechanic-requirements.rod_requirement` 将原版 `FISHING_ROD` 排除在插件机制外，用原版竿钓鱼不触发插件机制，因此不计分。

## 七、代码层面的实际行为

1. **调度是秒级精确匹配**：`BukkitCompetitionManager.timerCheck()` 每秒跑一次，用「星期 + 时 + 分 + 秒」去 `timeConfigMap.get(...)` 精确取配置。10:00:00 那一刻服务器没开，当天就不会开赛，只能手动 `/cfishing competition start <id>`。
2. **reload 会立刻结算进行中的比赛**：`unload()` 对进行中的赛事调用 `stop(true)`，12 小时的长赛在比赛期间执行 reload 会被直接颁奖结束。
3. **奖励档位按子键数量判定**：`Competition.java` 用 `if (i < rewardsMap.size())` 判断名次是否落在名次奖区间，取的是 **map 的子键个数**而不是 key 名。若把 `participation` 整个删掉，子键数变成 3，第 3 名（`i = 3`）会掉进 else 分支拿到 `null`，静默丢奖。所以「取消参与奖」必须保留第 4 个键，用 `chance: 0` 的动作占位。
4. **离线不发奖**：结算时用 `Bukkit.getPlayer(name)` 取人，只给在线玩家发钱与物品；参赛后下线，名次保留但奖励拿不到。
5. **新赛会顶掉旧赛**：`start()` 若检测到已有进行中的比赛，会先 `end(true)` 立即结算发奖，1 秒后再开新赛。
6. **同时间点互相覆盖**：调度表以「星期 + 时 + 分 + 秒」为键，两个赛事配到同一时间点时后注册的会覆盖前者，且不报错。
7. **周期广播按「已用时长取模」触发**：`(durationInSeconds - remainingTime) % (interval / 20) == 0`，即相对开赛时间每满一个 `interval` 发一次（`interval` 单位为 tick，30 分钟 = 36000）。计时器每秒一跳，服务器卡顿跳过某一秒时会静默少发一次，不会补发。
8. **周期广播固定发给全服在线玩家**：`Competition#broadcast()` 直接遍历 `Bukkit.getOnlinePlayers()`，配置里的 `only-show-to-participants` 被解析进 `showToAll` 但未被使用，所以广播不区分参赛者。
