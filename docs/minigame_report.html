难度评级怎么来的

精准点击看「指针穿过命中区的毫秒数」并以命中区占比修正（<0.25s 为人类反应极限，记 5 星）； 长按跟随看「判定区占整条的比例 + 需累计按住秒数」；张力控制看难度中值（决定挣扎触发频率与张力增幅）； 急速收线换算成「每秒需点击次数」；音游看「动作数 × 按键种类」，且错一次立即失败。

每种鱼会抽中哪些难度的小游戏

抽奖分两步：① 先按 game-conditions.yml 的权重抽出小游戏 ID—— 所有条件成立的场景 / 子组权重累加进同一张表再抽；② 抽中后才在该游戏自己的 difficulty 区间（如 15~30）内随机 roll 一个值，最后按 roll值 × difficultyMultiplier + difficultyAdder 叠加装备 buff 并钳制在 1~100 （buff 来源为钓竿 / 鱼钩 / 装备 / 鱼饵的 type: difficulty 与 type: difficulty-multiplier，只改难度数值、不改抽中概率）。 因此同一种鱼每次开局，难度只会在下表各游戏的区间内浮动。53 种鱼中 4 种 special_game 剧情鱼走独立奖池，其余按「所在环境 / 生物群系 + 星档」抽奖； 色点与上方五种机制一一对应。

抽奖与结算全流程

从抛竿到结束的完整链路（源码：CustomFishingHook / VanillaMechanic / AbstractGamingPlayer）。关键结论：最终鱼种在浮标入水瞬间就已抽定—— 比咬钩更早，比小游戏更早；小游戏只决定这条已抽定的鱼「给不给」，失败即丢弃。
抛竿→浮标入水【抽鱼定种】→等待咬钩→咬钩→右键收线→抽小游戏 ID→roll 难度（叠加装备 buff）→小游戏→成功给鱼 / 失败弃鱼→销毁钩子
阶段触发时机代码位置发生什么
① 抛竿右键抛出浮标CustomFishingHook:132-134 应用 CAST 阶段效果；按环境选出 HookMechanic（水 = VanillaMechanic，熔岩 / 虚空各有专用）；启动每 tick 轮询任务
② 抽鱼定种浮标入水瞬间（canStart = 入水）CustomFishingHook:150-233 getNextLoot() 抽出最终鱼存入 nextLoot；合并该鱼的 baseEffect + 装备 phase-2 修正 → tempFinalEffect 落定；mechanic.start() 设定咬钩等待时间。抽不到鱼 → freeze，玩家永远空竿
③ 等待咬钩入水后 100~1200 tickVanillaMechanic:85-119 每 tick 检测咬钩状态；等待时间 = 原版计时 × waitTimeMultiplier + adder（或配置区间随机）；等待中脱钩 → ESCAPE 事件并重新计时
④ 咬钩浮标抖动CustomFishingHook:408-423 BITE 事件；自动钓鱼条件满足 → 直接发鱼不玩小游戏；instantGame 的鱼 → 立即开小游戏，不等收线
⑤ 收线玩家右键收线CustomFishingHook:381-403 未咬钩 → 空竿销毁；已咬钩且 disableGame / skip-game 条件满足 → 直接发鱼；否则进入小游戏
⑥ 小游戏开局收线（或 instantGame）gameStart():335-353 权重累加 → 抽游戏 ID → 难度区间 roll + 装备 buff 修正（clamp 1~100）→ mechanic freeze（等待时间锁 MAX_VALUE，防止游戏中浮标变状态）
⑦ 判定操作 / 超时AbstractGamingPlayer:202-240 每 tick 运行 + 超时检查；endGame() 按 isSuccessful() 分流
⑧ 结算游戏结束CustomFishingHook:457-660 成功：数量（multipleLootChance）→ 生成物品（size 在此用 SIZE_MULTIPLIER/ADDER 求值）→ 统计记录；失败：已抽定的鱼直接丢弃，什么都不给；随后销毁钩子，自动钓鱼自动抛下一竿
绕过小游戏的路径：disable-game: true 的鱼（本项目约 20 处：default.yml 的原版鱼 + entity 类掉落）收线即得；自动钓鱼（auto-fishing 条件）咬钩即得；skip-game 条件满足也可跳过； instantGame: true 则咬钩立即开局。时序细节：抽鱼用的是 LOOT 阶段效果，鱼的 baseEffect 是抽中之后才合并的——所以一条鱼自己的 base-effects（含 difficulty-adder） 能改它自己的小游戏难度，但改不了抽中过程。

值得注意的几点

  1. 精准点击占了 74%（34/46）：7 个 rainbow 变体 + 9 种 bar × 3 档。但它在场景里只服务于 「非海洋水域」（river_games，权重 12/档）和彩虹鱼专属战利品；海洋、熔岩、虚空都没有精准点击。
  2. rainbow_1~7 参数完全相同，只有命中色段和标题颜色不同（难度均回落到默认 20~80、7 段、窗口 130~390ms），可以理解为同一条传说鱼关卡的 7 个配色变体，而不是 7 种不同玩法。
  3. 金星档没有回收 easy 权重：river_games 的 golden 档里 dance_game_easy 仍占 12.7%， ocean_games / lava_games 的 golden 档里 click_game_easy 仍占 26.7% / 25%—— 金色星标鱼反而更容易抽到简单机制，与「星标越高越硬」的设计意图相反，疑似漏配负权重。
  4. 张力控制的三档参数完全一致（上限 50、收线 144 格、+1/+2/-2），只有 difficulty 不同， 难度差异全靠「挣扎触发概率 = difficulty/4000 每 tick」和张力增幅 difficulty/50 撑起来。
  5. 耗时分布：急速收线 10~12s 最短，音游 15~18s，其余统一 30s；rainbow 与 accurate_click_bar_1_easy 为 15s。
  6. click 的 difficulty 直接等于需要点击的次数（15~60），没有独立参数， 调难度只能改 difficulty 数字。
  7. 鱼先抽定，小游戏只是闸门：最终鱼种在浮标入水瞬间（收线与小游戏之前）就已抽定， 小游戏失败则这条鱼直接丢弃；先抽 ID 再 roll 难度、装备 buff 只改难度数值的完整链路 见上一节「抽奖与结算全流程」。
