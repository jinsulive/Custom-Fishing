# 钓鱼市场全局与固定物品价格

- 全局配置：`core/src/main/resources/config.yml` → `mechanics.market`
- 鱼价数据源：
  - `core/src/main/resources/contents/item/default.yml` → 17 种基础鱼，49 个带 `price` 的物品
  - `core/src/main/resources/contents/item/custom_fishes.yml` → 36 种扩展鱼，108 个带 `price` 的物品
- 公式实现：`BukkitConfigManager`（`price` 物品解析器，优先级 1500）、`BukkitMarketManager#getItemPrice`
- 结算实现：`BukkitMarketManager`、`MarketGUI#refresh`

> 术语约定：
> - **{base} / {bonus} / {size}** —— 全局公式的三个变量，分别取自鱼的 `price.base`、`price.bonus` 与本次钓获随机出的体长。
> - **单价（Price）** —— 物品生成瞬间按公式算出并写进 NBT 的 `Price` 标签，之后固定不变。
> - **售价** —— 单价 × 数量，再乘 `earnings-multiplier`。
> - 普通 / 白银之星 / 黄金之星是配置文件里三条独立的物品定义，不是同一物品的品质字段。

## 一、售价相关全局参数

| 参数 | 当前值 | 说明 |
|---|---|---|
| `price-formula` | `{base} * 0.2 + {bonus} * {size} * 0.1` | 自定义战利品的定价公式；代码内默认值为 `{base} + {bonus} * {size}` |
| `earnings-multiplier` | `1` | 全局收益倍率，支持表达式 |
| `limitation.enable` | `true` | 是否启用每日收益上限 |
| `limitation.earnings` | `"5000"` | 每名玩家每日可赚取的上限，支持表达式 |
| `item-price` | 5 条，值全为 `0` | 原版物品与 CMD 物品的固定价格表 |
| `item-slot.allow-items-with-no-price` | `false` | 价格为 0 的物品无法放入市场槽位 |

## 二、售价判定顺序

`getItemPrice` 按以下顺序短路，命中即返回：

1. **NBT `Price` 标签**：读出后 `× 数量`。`default.yml` 与 `custom_fishes.yml` 中的鱼走这条路径，不再查任何价格表。
2. **收纳袋（Bundle）**：满足 `allow-bundle-requirements` 时递归累加袋内物品。
3. **潜影盒**：满足 `allow-shulker-box-requirements` 时递归累加盒内物品（当前条件为 `impossible`，该路径不成立）。
4. **`item-price` 固定表**：键为 `MATERIAL` 或 `MATERIAL:自定义模型数据`，命中后按表内值 `× 数量`。
5. **全部未命中 → 0**，即不可出售。

单次结算总额 = 槽内各物品售价之和 × `earnings-multiplier`；一键出售总额 = 背包（及钓鱼袋）内可售物品之和 × `earnings-multiplier`。

结算以物品上的 `Price` 标签为准，不校验该标签的写入来源。

## 三、全局公式与求值

```
{base} → 鱼配置 price.base  → MathValue 求值（可写表达式/占位符）
{bonus} → 鱼配置 price.bonus → MathValue 求值
{size}  → size 配置区间内随机值，叠加体长加成（SIZE_MULTIPLIER / SIZE_ADDER）
```

- 解析顺序保证 `size`（优先级 1000）先于 `price`（1500），公式里的 `{size}` 一定是已确定的本次体长。
- 渲染链路：`{base}` / `{bonus}` 先代入求值 → 套用 `price-formula` → 解析剩余占位符 → 未解析成功的占位符替换为 `0` → 表达式求值 → 写入 `Price` 标签。
- `mechanics.size.restricted-size-range: true` 会把加成后的体长夹回配置区间，因此体长加成只能把单价推到该鱼种区间的上限。
- 定价时点是物品生成瞬间。修改 `price-formula` 或鱼的 `base` / `bonus` 只影响之后钓到的鱼，已存在的鱼仍按原 `Price` 标签结算。
- 物品数量由鱼配置的 `amount` 决定（缺省 1），`Price` 是单品价格，结算时乘以堆叠数量。两份鱼配置中仅 `red_snapper_fish_silver_star` 配了 `amount: 7~9`，其余均为 1。

计算示例（樱花大马哈鱼，普通档 `base: 5`、`bonus: 0.5`，体长 30）：

```
5 * 0.2 + 0.5 * 30 * 0.1 = 1 + 1.5 = 2.50
```

## 四、固定物品价格表（`item-price`）

| 键 | 当前值 | 匹配对象 | 结算结果 |
|---|---|---|---|
| `COD` | 0 | 原版生鳕鱼 | 售价 0，不可出售 |
| `PUFFERFISH` | 0 | 原版河豚 | 售价 0，不可出售 |
| `SALMON` | 0 | 原版生鲑鱼 | 售价 0，不可出售 |
| `TROPICAL_FISH` | 0 | 原版热带鱼 | 售价 0，不可出售 |
| `PAPER:999` | 0 | `PAPER` 且 CustomModelData=999 | 售价 0，不可出售 |

键匹配规则：

- 严格全等。物品带 CustomModelData 时只查 `MATERIAL:CMD`，不回退到不带 CMD 的键；不带 CMD 的物品也不命中带 CMD 的键。
- 值为 `0` 与「不在表中」结算结果相同，均为不可出售。
- 未列入该表的原版物品（`STICK`、`KELP`、`SEAGRASS` 等）一律按 0 处理。

当前该表的实际效果是：原版鱼与 `PAPER:999` 被排除在可交易范围之外。

## 六、售价与每日上限

| 环节 | 当前行为 |
|---|---|
| 上限判定 | `totalWorth`（已乘 `earnings-multiplier`）大于剩余额度时，整笔交易被拒绝，不做部分成交 |
| 额度重置 | 按服务器本地日期判断，异步任务每秒轮询一次，跨日刷新在线玩家的已赚额度 |
| 倍率位置 | `earnings-multiplier` 在判定前乘入总价，因此提高倍率会同步加快额度消耗 |
| 关闭上限 | `limitation.enable: false` 时上限取 `-1`，判定被跳过 |
| 结算动作 | `give-money`（需 Vault + 经济插件），配置内另附注释掉的 `command` 动作作为替代写法 |
| 事件 | 出售前触发 `MarketSellEvent`，监听方可取消整笔交易 |

按当前数值，单日 5000 的额度对应的可成交量为：12 条黄金幼年利维坦（4744.80）可全额结算，第 13 条起触顶；若全部为普通档（单件均价 1.10 ~ 4.75），则需要约 1050 ~ 4550 件才能触顶。
